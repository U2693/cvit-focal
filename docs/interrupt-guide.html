Observing CPU6 Interrupts in biscvit

1. Use the TUI

Start an interactive WIPL boot:

BOOT_KEYS=$'F0\r' ./scripts/boot.sh

In the device panel, watch the interrupt line:

Interrupts     IPL 6  depth 1  FLAGS ...

When queued or typed terminal input is serviced, IPL briefly switches to 6. After the interrupt handler executes RI, the previous IPL is restored and interrupt depth returns to 0.

2. Watch interlevel registers

In the TUI, press g and enter 0060 to inspect the level-6 interlevel register bank.

AddressMeaning
0060IL6(A): terminal character/result consumed by WIPL
006EIL6(P): level-6 interrupt vector; this WIPL image sets it to 054F

WIPL installs its MUX interrupt handler like this:

05CF: LDA= 05A6
057B: ILST IL6(P),AX ; installs interrupt vector 054F at IL6(P)
057E: ILST IL6(A),AX ; clears IL6(A)
...
0588: ILLD IL6(A),AX ; foreground polls char left by interrupt

3. Break on the interrupt handler

Set a breakpoint at WIPL's level-6 MUX handler:

  1. Press b in the TUI.
  2. Enter 054F.
  3. Type a key at a WIPL prompt.

Execution should stop at the interrupt handler. The handler returns through:

054B: XIO ...
054E: RI           ; return from interrupt

4. Use trace logs

You can also capture a trace and grep for the handler:

BOOT_KEYS=$'F0\r0\r100\r' ./scripts/boot.sh --run --max 300000 --trace 2>trace.log
grep -n '054F\|054B\|054E' trace.log | head

Seeing execution enter 054F and later reach 054E: RI confirms that the level-6 interrupt path is active.
