biscvit quickstart

biscvit is a small C# terminal UI emulator/monitor for the Centurion CPU6.

Build

dotnet build

Run the bundled bootstrap + floppy image

./scripts/boot.sh

The script loads roms/bootstrap_unscrambled.bin, mounts roms/floppy.img, and configures the floppy geometry used by the local image.

Run the bootstrap + Hawk image

./scripts/boot_hawk.sh

The Hawk script defaults to ../CenturionComputer/Software/Data Packs/CENTOS_12.IMG. Override it with HAWK=/path/to/image ./scripts/boot_hawk.sh.

Useful scripted boot keys

BOOT_KEYS=$'F0\r' ./scripts/boot.sh
BOOT_KEYS=$'H0\r' ./scripts/boot_hawk.sh

Terminal input is old-system style: the monitor/WIPL wants carriage return (\r), not line feed (\n).

Common command-line forms

dotnet run -- --load roms/loopback.bin 0100 --pc 0100

dotnet run -- \
  --boot-rom roms/bootstrap_unscrambled.bin \
  --floppy roms/floppy.img \
  --floppy-sector-size 400 \
  --floppy-sectors-per-track 20 \
  --floppy-heads 1 \
  --floppy-tracks 77

dotnet run -- \
  --boot-rom roms/bootstrap_unscrambled.bin \
  --hawk "../CenturionComputer/Software/Data Packs/CENTOS_12.IMG" \
  --hawk-sector-size 400 \
  --hawk-sector-stride 512 \
  --hawk-sectors-per-track 16 \
  --hawk-heads 2

Useful debug flags: --trace for CPU tracing and --floppy-trace for FFC/floppy transfers. --ffc-linear-experimental is only for synthetic or historical experiments where FFC track/sector bytes are treated as a 16-bit linear block address; do not use it for normal FDIPL floppy booting.

Notes from WIPL debugging

  • After the bootstrap loads WIPL, code around 0588 is disk-image code loaded at 0100.
  • The loop at 0588 polls IL6(A) for terminal input.
  • Printable terminal characters are often converted to high-bit form: '1' becomes B1.
  • F201 is terminal data MMIO; writes appear in the terminal pane.
